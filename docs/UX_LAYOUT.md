# BYD Auto Sign：状态总览与设置页设计

> v0.5.1 页面整理。目标是在不改变签到协议、调度和授权逻辑的前提下改善信息层级；保留浅色/深色及 Android 动态色，避免引入常驻导航栏或冗余动画。

## 设计依据

- [Android Developers — Settings](https://developer.android.com/design/ui/mobile/guides/patterns/settings)：高频任务不应混在设置项中；设置使用清晰的主标签与状态说明，根据语义分组，复杂内容使用独立页面。
- [Android Open Source Project — Android settings design guidelines](https://source.android.com/docs/core/settings/settings-guidelines)：首页可快速理解当前状态及关键设置值，避免一次性堆叠过多选项，重要信息靠前。
- [Material Design 3 in Compose](https://developer.android.com/develop/ui/compose/designsystems/material3)：使用 Material 3 字体层级、语义色与原生组件，兼容系统动态配色。

## 当前页面结构

| 页面 | 主要内容 | 目的 |
| --- | --- | --- |
| 总览（默认） | 今日签到状态（最大视觉权重）、下一次计划与最近执行、主要操作、最近 3 条历史、授权摘要 | 一眼判断是否正常、是否需要操作 |
| 设置（右上角） | 自动签到开关、时间设置、闹钟权限、结果通知授权、微信重新授权 | 将低频配置集中在可发现但不抢占首页注意力的位置 |
| 签到记录（总览入口） | 最近最多 100 条实际执行记录 | 详细查看失败类别与尝试次数 |
| 运行诊断（设置入口） | Alarm/WorkManager 时间线、Hook/Binder/DEX 状态、重新探测 | 将技术状态与日常状态隔离，便于故障排查 |

## 状态优先级

1. **已签到**：今日已经完成，主操作不可再触发，显示下次计划。
2. **未授权**：提示初始化，并提供直接授权操作。
3. **今天尝试失败**：突出最近失败，允许手动重试；具体分类可从历史查看。
4. **已暂停**：提示自动调度关闭，但手动签到仍可用。
5. **等待签到**：显示自动任务已就绪以及下一次计划。

以上状态是业务状态，不能把微信 Hook 暂时离线直接判定为无法签到：已缓存会话可独立签到。运行诊断另行展示 Hook 连接状态。

## 交互约束

- 不变更原来的 `NativeSignManager` 业务接口、`SignCoordinator`、`SignScheduler`、`SignNotifier`。
- 时间和开关编辑后需明确点击「保存更改」；保存完成通过 Snackbar 反馈，不增加永久占位结果卡片。
- 成功/失败历史遵循现有数据模型，不把敏感会话及服务器原文显示在 UI。
- 「今日已签到」主按钮禁用，重复调度与重复通知的底层防护保持原实现。
- 诊断内容长时独立滚动，首页不直接显示多行技术输出。

## 验收重点

- [ ] 亮色、暗色及系统动态色的视觉层级
- [ ] 未授权、已签到、最近失败、自动调度关闭的主状态优先级
- [ ] 设置保存后重启应用仍显示真实配置
- [ ] 系统通知权限/闹钟权限返回页面后的状态
- [ ] 新手能从首页授权和立即签到，高级用户能找到 DEX 探测与调度诊断
- [ ] 小屏幕与系统字体放大时无溢出，系统返回可返回首页
